# Ignition - Dealer Operations (by Revolution)

A Progress Agentic RAG (ARAG) concept demo built for **Revolution** (rev.com.au), the
Australian/NZ dealer-management ISV behind SHOWROOMnext - a Play 3 (ISV embed) pursuit
asset. This is a rebuild of the archived `apps/revolution-dms` demo: a fresh Knowledge
Box, a fresh synthetic dealer-operations corpus, and the same real captured Revolution
identity, carried into a new information architecture and use-case set.

**Framing (read this first):** this is an illustrative concept of what Agentic RAG could
add *inside* a platform like Revolution's own SHOWROOMnext - an embeddable AI layer an ISV
could ship to its own dealer customers. It is deliberately **not** branded SHOWROOMnext and
makes no claim about that product's actual internals; the fictional product name is
"Ignition" so nobody mistakes this for Revolution's real, shipped system. The visual
identity - primary blue `#2964F6`, the navy-to-blue gradient direction, the deep-navy
panel tones, and the ring/orbit wordmark motif - is Revolution's own, captured from
rev.com.au for this pitch. See `content/demos/revolution-brand-capture.md` (factory root)
for the full capture: sources, pixel-sampled hex values, and confidence levels.

The dealer-side fiction - **Coppermill Motor Group**, a multi-site Australian dealer group
(Riverside and Northgate sites, 14 units of stock across cars, utes, SUVs and
motorcycles) - is the fictional CUSTOMER using Ignition day to day. The real identity in
this build belongs to the ISV whose product this is (Revolution); the dealer group and
every document in its library are synthetic, disclosed as such in the app footer.

## Why this exists

Dealer operations staff work across recon manuals, recall bulletins, consultant field
notes, supplier records and parts cross-reference sheets scattered across folders and
memory. Ignition puts a single, cited, grounded assistant in front of all of it, plus
four adjacent workbenches that show different genuine Progress Agentic RAG mechanisms at
work: catalogue intelligence, structured diagnosis, a real media library, and
unstructured-to-structured analytics.

## The five use cases (one route each)

| Route | What it proves |
|---|---|
| `/service-assistant` | Grounded Q&A over the recon/standards library, inline `[n]` citations, a REMi-derived confidence badge, click-through to the exact highlighted passage. |
| `/compliance` | A recall/bulletin/compliance catalogue - real per-item titles, summaries and highlights generated by a genuine Progress Agentic RAG structured-answer call over each document's own text, not hand-typed copy. |
| `/media-library` | A recon-photo library backed by real KB file resources; thumbnails stream through the server proxy (the credential never reaches the browser), faceted by site. |
| `/deal-desk` | Pick a stock number - the server fuses the vehicle's own record (its own system of record) with a genuine Progress Agentic RAG structured diagnosis and citations, drawn from that vehicle's consultant note and the relevant recon standard or recall bulletin. |
| `/insights` | Charts built from a REAL unstructured-to-structured extraction: issue category, severity and risk flags pulled from free-text consultant notes by a query-time `/ask` + JSON-schema call, never a GROUP BY on an existing coded field. |

`/` is the launcher home - live stock stats (the app's own system of record) and one
click into each workbench. Every route carries a top-right "How this works" reveal,
specific to that page, naming the real mechanism behind it.

## B47 self-declaration - what's real, mapped to the mechanism that powers it

Every apparent capability below is a genuine Progress Agentic RAG call at run time. No
capability is mocked, hardcoded, or staged.

- **Service & Recon Assistant grounded answers** -> `POST /kb/{id}/ask` against the
  `ignition-ops-assistant` search configuration (registered on the KB, visible in the
  console), citations enabled, reranked. Confidence badge derived from a real
  `/predict/remi` call scored against the FULL retrieved paragraph set.
- **Inline `[n]` citation markers** -> ARAG's own citation character-offsets (the `citations`
  field on the `/ask` response), snapped to word boundaries and grouped server-side - not
  model-placed, not invented.
- **Compliance/Media catalogue copy** (title, summary, highlights) -> a real query-time
  `POST /ask` with `answer_json_schema`, seeded with each resource's own extracted text
  (or, for media, its own recon metadata), computed once by `scripts/generate_catalog_copy.py`
  and cached. This is the WORKING structured-JSON mechanism - never the confirmed-broken
  ingest-time DA Generator task (see `arag-kb` skill gotcha 9).
- **Media Library thumbnails** -> Nuclia's own platform-native extracted `resource.thumbnail`,
  streamed through the server proxy.
- **Deal Desk diagnosis** -> two parallel real `/ask` calls (a schema call for the
  structured diagnosis, a citations call for provenance - the platform crashes if you
  combine `citations: true` with `answer_json_schema` in one call, see gotcha 4) fused
  server-side with the vehicle's own deterministic record. This is disclosed in the reveal
  as **app-orchestrated fusion, not an autonomous agent** - it does not claim a Retrieval
  Agent orchestrates it.
- **Dealer Insights charts** -> a real query-time `/ask` + `answer_json_schema` call per
  consultant note (14 calls total), extracting issue category/severity/risk from free
  text; the server only does deterministic arithmetic (counting) on top of that real
  extraction. No chart value could be produced by grouping an existing database column.
- **Honest decline** -> the KB's `ignition-ops-assistant` search configuration carries a
  system prompt asking for a warm, specific decline; the platform's fixed
  `"Not enough data to answer this."` lead sentence (unconfigurable - see the `arag-kb`
  skill) is stripped and replaced with in-voice copy at the render layer, never a silent
  invented answer.

**What this build deliberately does NOT attempt:** a live Retrieval-Agent-over-MCP
("watch it work") surface. The confirmed platform bug in the ARAG dashboard's RAO
node-graph editor (registered-MCP-agent step under a Smart Agent node not saving cleanly -
see the archived `apps/revolution-dms/BUG.md` for the original repro, and CLAUDE.md's
"Known live platform fragility" note) is systemic, not per-app, and was still open at
rebuild time. Rather than build another disclosed-fallback surface around a broken
mechanism, this rebuild scoped its five use cases to mechanisms that are confirmed working
today (`/ask`, `/find`, `/predict/remi`, query-time structured JSON) and is honest about
that scoping in the Deal Desk reveal, rather than presenting app-orchestrated fusion as if
it were agentic orchestration.

## Model tiers and cost (hard rule 15)

Every generative call - `/ask`, the structured-JSON catalogue-copy and insights
extraction, and the KB's own default - is pinned to **`gemini-3.1-flash-lite`** (the
cheapest capable tier on this account), never inherited from a premium default. Total
one-time cost to seed: ~74 generative calls (60 catalogue-copy + 14 insights extractions)
on the cheapest tier, well under a dollar. No corpus-wide graph extraction or DA task runs
on this KB.

## Architecture

```
Browser (static HTML + vanilla JS)
  -> Ignition FastAPI server (main.py) - the KB service-account token lives here only
    -> POST /kb/{id}/ask              grounded Q&A, citations, structured JSON
    -> POST /kb/{id}/predict/remi     REMi trust scoring
    -> GET  /kb/{id}/resource/{id}    extracted text, thumbnails
```

Knowledge Box: `ignition-dms-clean` (id `304d57b7-a6b7-4c04-b254-43a773c00a46`), account
`progress-jay-geo`, zone `<zone>`. ~60 resources: 46 text documents (recon
manuals, recall/service bulletins, compliance policy, supplier reliability records, parts
cross-reference sheets, 14 consultant field notes, 10 marketing spec sheets) plus 14
recon-photo images.


## 30-second reset

```
.venv/bin/python seed.py --purge
```

Deletes every resource on the KB, regenerates the synthetic corpus and media, re-ingests
everything, and recomputes the two ARAG-backed caches (catalogue copy, insights) fresh.
Restart the server afterward (or `POST /api/admin/reload-caches`) to pick up the new
caches without a redeploy.
