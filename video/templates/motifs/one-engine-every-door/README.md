# Motif: one engine, every door (`m-oe`)

The organised body shrinks to the ENGINE MARK - the bounded, tabbed doc-tile body from
the body-of-knowledge motif, miniaturised (280x216 at centre), so the hero symbol is the
same object the viewer watched being built, never a keypad. A LARGE generic sign-in
window (860px: chrome bar, avatar, two fields, button) takes centre frame at "not
another app" and is pushed off decisively. Request/answer pulses are legible: a question
chip travels in, an answer card travels out; a dashed orbit guide turns while tools call
on the engine. Five doors - website, service desk, mobile, CMS, staff portal, each in
its own chrome - arrive one per phrase, a connector drawing from the engine as each is
named, the SAME answer card landing in every door. On "every door" everything lights,
then answer dots flow down every connector. Performs: API-first, one engine behind
every surface. The engine is never alone on an empty stage for more than ~2s.

**When to use:** embed/API/integration beats; the "not another destination app" claim.

**Variables:** `oeEngine` (default "Answering engine"), `oeDoor0..oeDoor4` (door labels,
defaults Website / Service desk / Mobile app / CMS / Staff portal).

**Timing:** internal timeline 23.1s; mark forms 0.5-2.6, big window 4.45-6.85, label 7.3,
chip/card pulses 7.0-10.9, doors at DOOR_AT = [11.0, 12.0, 13.55, 14.65, 16.35]
(re-derive from the narration alignment), one-engine pulse 18.35, every-door light-up
19.3, connector flow dots 19.9+, floating tail. Engine box left 820 top 452, 280x216
(centre 960,560) - match any adjacent scene that hands the mark off.
